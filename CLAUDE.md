# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the App

No build step — open directly or serve locally:

```bash
# Direct open
xdg-open index.html

# Local HTTP server (required for service worker to register)
python3 -m http.server 8080
# then visit http://localhost:8080

# VAT parity test suite (12 cases — must stay 12/12)
node tests/vat.test.js
```

No dependencies, no package manager, no transpiler.

**Stale Service Worker cache during local dev**: once the SW registers (any `http.server` visit), it cache-first-serves `./src/*.js`. If you edit a file under `src/` and a reload doesn't reflect the change, the SW is serving the previous `portbill-vNN` cache — bump the `CACHE` version in `sw.js`, or in DevTools run `(await navigator.serviceWorker.getRegistrations()).forEach(r=>r.unregister()); (await caches.keys()).forEach(k=>caches.delete(k))` and hard-reload.

## Architecture

One markup file, six logic modules under `src/`, one stylesheet, plus the PWA/Worker support files and a `tests/` folder — everything is self-contained vanilla JS/CSS, no bundler:

- **`index.html`** — Markup only. Six module pages (`#page-car`, `#page-cargo`, `#page-reexport`, `#page-rotation`, `#page-saved`, `#page-stats`) plus three `<dialog>` elements: admin login (`#overlay`), print preview (`#ppvDialog`), and reusable confirm (`#confirmDialog`). Module switching is tab-driven via `switchModule()`; the rotation/saved/stats tabs are `hidden` unless admin — Re-Export, like Car and Cargo, is a public tab. Header also carries `#syncBadge` (`.hbadge.sync-badge`, `hidden` by default) — the offline/pending-sync indicator, see **Offline sync resilience** below.
- **`src/`** — All logic (~7,030 lines total), split into six single-responsibility classic `<script defer>` files (no bundler — plain scripts sharing one global scope, loaded in this fixed order; `src/core.js` MUST load first, `src/platform.js` MUST load last). Each `<script>` is still just top-level `function`/`const` declarations, so every function remains a plain global exactly as before the split — no `window.fn =` wiring, no import/export. Sections within each file are still marked with `// ════` banners inherited from the pre-split layout.
  - **`src/core.js`** — Shared kernel every other file depends on: debug logger (`DEBUG`/`dbg`), **VAT — MPA parity** (`calcVATmpa(totalBillBDT, vatPercent)` — the ONLY VAT rounding path; integer poysha-scale math + half-to-even/banker's rounding, mirroring the MPA C# engine `Math.Round((TotalBillBDT ?? 0) * VATPercent / 100m, 2)`; callers pass the fractional rate scaled up: `calcVATmpa(base, vatRate * 100)` — see **Rounding** below), rate persistence (`RATE_DEFAULTS`, `localStorage` key `pb_admin_rates`, `loadSavedRates()`/`saveRates()`/`resetRatesToDefaults()`), toast (`showToast`), field-validation helpers (`isValidDateStr`, `setFieldState`, `validateDateField`, `validateDateOrder`), admin session state + crypto primitives (`isAdmin`, `_sessionWriteToken`, `hashText`, `getAdminPasswordHash`), shared cross-module state (`currentModule`, `lastCarBill`/`lastCargoBill`/`lastReexportBill`, `editingBillNumber`, `domCache`, `partBillingStages`, `reexportBEs`, etc. — centralized here specifically so every feature file can read/write them as ordinary globals), general utils (`escHtml`, date/number helpers, `gn`/`gb`/`nn`, `saveBill`/`getSavedBills`/`persistSavedBill`), the shared `calcSlabs()` slab calculator, pre-calculate input-error collectors (`collectCarErrors`, `collectCargoErrors`, `reportInputErrors`), the relocated `PROXY_URL` constant, **`ceilTon(v)`** — see **Tonnage rounding** below — and the **offline-sync pending-write tracker** (`ROTATIONS_KEY`/`SYNC_PENDING_KEY` `localStorage` keys, `getPending()`/`markPending(resource)`/`clearPending(resource)`) — see **Offline sync resilience** below.
  - **`src/admin.js`** — `switchModule()`/`updateAdminNavigation()` (module-tab nav guard), admin auth (`toggleAdmin`, `doLogin()` using `crypto.subtle` against `AP_HASH`, locked after 5 attempts via sessionStorage; on success the entered password is stored in `_sessionWriteToken` for Worker PUT auth, and `flushSync()` fires immediately in case admin-gated writes — rotations/config — were queued while logged out), `changeAdminPassword()`, and cloud rate-config restore (`applyAdmin()`).
  - **`src/car.js`** — Car wharfage engine: `carCompute()` → `calcSlabs()` → `buildCarBillTable()` → `carCalculate()` writes to DOM; `carRefresh()` is the live-preview debounce wrapper. Both `rHoisting` (`rLanding × 1.25 × 0.50`, weight > 3t) and `rRemoval` (`rLanding × 2`, MPA Tariff §8.3 manual removal, unconditional) are **derived, not stored** — recomputed every cycle in `carRefreshNow()`, absent from `RATE_DEFAULTS`, and their `<input>`s are `readonly`/`placeholder`-only. Saved/draft bills snapshot the DOM value at save time, so restoring an old bill replays its original figure even if Landing Rate has since changed admin-side. Also owns the **Rotation Number registry UI** (car-only integration: `loadRotations`/`addRotation`/`deleteRotation`/`renderRotationTable`/`refreshRotationInBill`) — the worker I/O half of rotations (`saveRotationsToWorker`, `putHeaders`) lives in `platform.js`. `loadRotations()` writes every successful fetch to the `ROTATIONS_KEY` `localStorage` cache and falls back to that cache on fetch failure, so the rotation dropdown/table survives offline/network-error startup instead of rendering blank; `addRotation()`/`deleteRotation()` (v3.12.1) commit to `_rotations` + the `ROTATIONS_KEY` cache and re-render **unconditionally**, before attempting `saveRotationsToWorker()` — the local mutation is never gated on the network call succeeding, matching the offline-first pattern used by `persistSavedBill()` and `changeAdminPassword()`. On a failed push the status line reads "…added/deleted — will sync when online" (new `.rot-reg-status.warn` amber state) and `saveRotationsToWorker()`'s `markPending('rotations')` lets `flushSync()` retry once online — see **Offline sync resilience** below.
  - **`src/cargo.js`** — General Cargo billing: `cargoCompute()` is the main compute function; part billing is driven by `computePartBillingWharfrent()`; self-drive tons use `calcCarBillingSdSlabs()` (same slab table as Car).
  - **`src/reexport.js`** — Re-Export / transhipment MPA tariff engine. State is a nested array `reexportBEs` (Bill of Entries, each with a `clds[]` array of `{date, ton}` lots and an optional `removalTon`) — rendered by `renderBillOfEntries()` with `addBillOfEntry()`/`removeBillOfEntry(bi)`/`addCld(bi)`/`removeCld(bi,ci)` mutators. `getReexportLandingRate(totalTon)` picks the Tk 90/180/250 slab; `calcReexportWharfRent(...)` is a 20-day-free-time, 5/15-Tk-tiered wharf-rent calculator — **not** the Car/Cargo `calcSlabs()` (7/14/15-day convention); the two are not interchangeable. `reexportCompute()` returns `beResults[]` plus combined `vatBaseTotal` → `calcVATmpa(...)` → `grandTotal`; `collectReexportErrors()` enforces Edge Case ① (Re-Export Date must be strictly after every CLD it bills).
  - **`src/platform.js`** — Cross-cutting platform services, **loaded last** (its top-level INIT block runs the app bootstrap once every other file's globals exist): **Invoice/print** (`buildInvoiceHtml(opts)` builds the full print document as an HTML string; `openPrintPreview()` injects it into the `<iframe>` inside `#ppvDialog`; accent theming via `opts.accent` — `"car"`|`"cargo"`|`"reexport"` → gold/sky/teal); **cloud sync** (`putHeaders()`, `saveRotationsToWorker`, `saveBillsToWorker` — no admin gate, bill saving is open to all users — `saveConfigToWorker`, `loadConfigFromGitHub()`, `loadBillsFromWorker()` — cloud is source of truth on startup, all use the shared `PROXY_URL` from `core.js`); **offline sync resilience** (`updateSyncBadge()`, `flushSync()` — see below); **draft auto-save** (`saveDraft(type)`/`clearDraft(type)`/`getDraft(type)`/`restoreFormDraft(type)`, `localStorage` keys `pb_draft_car`/`pb_draft_cargo`/`pb_draft_reexport`, 24h TTL, `setInterval` every 10,000ms); **usage analytics** (`getDeviceId()`, `trackVisit()`, `loadStats()`, `renderStats()` — day keys use Asia/Dhaka/UTC+6, `statsDayKey()` must stay formula-identical to the Worker's `dhakaDay()`); **saved bills** (`renderSavedBills()`, `editSavedBill()`, `printSavedBill()`, `deleteSavedBill()`); and the **INIT block** itself (date defaults, `loadSavedRates()`, initial `carRefresh()`/`cargoRefresh()`/`reexportRefresh()`, admin-access listener, `online`/`offline` window listeners) plus the `window.carReset`/`window.carCalculate` rotation-integration overrides.
  - **`confirmModal()`** (in `core.js`, alongside `showToast`): Reusable in-app confirm dialog (Promise-based). Replaces all native `confirm()`/`window.confirm()` calls, using the `#confirmDialog` native `<dialog>` element — same `showModal()`/`close()` pattern as `#overlay`.
- **`style.css`** — All styles (~4,870 lines). Uses CSS custom properties for the color palette, including the `--accent` system (see below). `@media print` rules at the bottom. `.ro` class makes rate inputs read-only visually (dashed border, reduced opacity). Full responsive polish at breakpoints from 320 px to 4K; mobile improvements at `@media (max-width: 480px)`.
- **`worker.js`** — Cloudflare Worker proxy. `GET` endpoints are open. All `PUT` endpoints require `Authorization: Bearer <token>`; the token's SHA-256 is verified against the `WRITE_TOKEN_HASH` Cloudflare secret (set via `wrangler secret put WRITE_TOKEN_HASH`). If the secret is absent, PUT returns 503. Usage analytics routes need a **D1 binding `DB`** (table `visits (day, device, opens, PK(day, device))`, index `idx_visits_day`): `POST /track` is open (validated device id, one upsert per day+device), `GET /stats` is guarded by the same `WRITE_TOKEN_HASH` bearer check as PUTs and returns exact `COUNT(DISTINCT device)` buckets (today / 7 / 30 days / all-time) plus a per-day series. **Live in production** — the `portbill-stats` D1 database is provisioned and bound; `wrangler.toml` (repo root) pins `name`, `main`, and the `[[d1_databases]]` binding so `wrangler deploy` alone redeploys with correct bindings (no dashboard step). `WRITE_TOKEN_HASH` is not yet set as a secret, so `/stats` (like PUT) is currently open — same "personal use" default described above.
- **`manifest.json`** — PWA web app manifest: `name`, `short_name`, `display: standalone`, `theme_color: #020202`, `icons` pointing at `favicon.svg`.
- **`favicon.svg`** — Compass-rose emblem SVG (gold stroke `#c09230`). Also used as `apple-touch-icon` and PWA icon.
- **`sw.js`** — Service worker. Cache name: `portbill-v17` (increment on each deploy). Caches `./`, `index.html`, the six `./src/*.js` files, `style.css`, `favicon.svg`, `manifest.json`. Strategy: cache-first with background network update (stale-while-revalidate). Only intercepts same-origin GET requests. **When deploying a new version, bump the cache name to invalidate stale caches** — this matters more now than with a single file, since a stale-cached `src/*.js` can silently serve pre-refactor logic; when in doubt during local testing, unregister the SW and clear caches rather than trusting a plain reload.
- **`tests/vat.test.js`** — VAT MPA-parity suite (12 cases incl. half-to-even midpoints and null safety). Runs with `node tests/vat.test.js`; extracts `calcVATmpa` from `src/core.js` at runtime so the shipped source is tested, not a copy — `calcVATmpa` must stay a bare `function` declaration with a column-0 closing `}` for the extraction regex to match. Exit code 0 = all pass.

## Key Design Patterns

**Rounding**: All monetary values **except VAT** use round-half-**down** to 2dp via `r2 = (v) => (Math.ceil(v * 100 - 0.5) / 100) || 0` (port convention — a value exactly on the 0.5-cent boundary rounds down, e.g. 60,394.725 → 60,394.72). `Math.ceil(x - 0.5)` is the canonical "round half down" formula. The `|| 0` guard prevents `-0` from surfacing in output fields. Do not revert to `Math.floor(v*100+0.5)/100` — that formula rounds half-up and was replaced in v3.6.1 to match Port Authority convention. `r2` is defined locally inside each billing function scope (`carCompute`, `buildInvoiceHtml`, `computePartBillingWharfrent`, etc.) and named `rp2` / `_rp` in some helper contexts — all use the same formula.

**Rounding exception — VAT (v3.7.1)**: Every VAT amount is computed by the shared `calcVATmpa(base, vatRate * 100)` (top of `src/core.js`), which uses integer poysha-scale math (no float64 drift) and **half-to-even (banker's) rounding** — exact parity with the MPA C# billing engine (`Math.Round` defaults to `MidpointRounding.ToEven`). The two conventions differ only at exact `.xx5` midpoints with an odd poysha quotient (e.g. 15.70 × 15% = 2.355 → `r2` gives 2.35, MPA/`calcVATmpa` gives 2.36) — this was the source of 1-poysha VAT mismatches against printed MPA bills. Never use `r2` for a VAT amount, and never use `calcVATmpa` for anything other than VAT. Any change to `calcVATmpa` must keep `node tests/vat.test.js` at 12/12.

**Tonnage rounding — whole numbers only (v3.11.0)**: Every weight/tonnage value across Car, Cargo, and Re-Export is a **whole number, rounded UP**, via the shared `ceilTon(v)` in `src/core.js`: `Number.parseFloat` the input, `Math.ceil` it, clamp negative/non-finite to `0`. This is the *only* intentional behavior change from the pre-refactor app — before v3.11.0, Car/Cargo weights used `Math.round` (nearest) and Re-Export tonnage had **no** integer rounding at all (fully fractional). `ceilTon` replaced every such site: Car's `weight` (`carCompute`/`carRefreshNow`), Cargo's total/inside/outside/removal/weighment tons (`cargoCompute`/`cargoRefreshNow`/`cargoValidate*`), Self-Drive tons (`pbMaxWeight`/`pbMaxSdWeight`), Part-Billing stage balances (`pbBalanceChange`/`pbSdBalanceChange`), and Re-Export's BE/CLD/removal tons (write-back `oninput` handlers in `renderBillOfEntries()`, `reexportCompute()`, `collectReexportErrors()`). Never use `Math.round`/`Math.floor`/raw `parseFloat` on a weight or tonnage value — always `ceilTon`. Money (`r2`) and VAT (`calcVATmpa`) rounding are unaffected and remain as documented above.

**VAT/Levy presentation differs by module — they are intentionally NOT the same:**

- **General Cargo** — VAT and Levy are charged **ONCE on the COMBINED inside+outside base**, shown a single time at the foot of the bill. `cargoCompute` exposes per-portion sub-totals `iBase`/`oBase` (= wharfrent + payables, the VAT base) plus the combined `gBase = r2(iBase + oBase)`, `gVat = calcVATmpa(gBase, vatRate × 100)`, `gLevy = iLevy + oLevy`, `gTotal = r2(gBase + gVat + gLevy)`. The inside/outside sections show only their `*Base` sub-total; a single "BILL SUMMARY" block (`buildCombinedSummaryTable` on screen, `buildCombinedSummaryPrintSection` in print) renders `gBase → gVat → gLevy → gTotal`. This is a display choice (VAT shown once) **and** a correctness one: per-portion VAT that is summed double-rounds and drifts a cent when both portions hit a half-cent boundary (symptom: cargo grand total `…441.94`/`.96` instead of `.95`). The cargo print/part-billing builders recompute toggle-adjusted `gBase/gVat/gLevy/gTotal` when the payable/wharfrent toggles exclude charges.

- **Car** — Inside (full rate) and Outside (½ rate) are each a **COMPLETE bill**: `iBase + iVat + iLevy = iTotal` and `oBase + oVat + oLevy = oTotal`, with VAT/Levy shown **per section** (`iVat`/`oVat` each via `calcVATmpa`). The Car Grand Total is `iTotal + oTotal`. `carCompute` returns `iVat`/`iTotal`/`oVat`/`oTotal` (no `g*` fields). Do not apply the cargo combined-VAT model to the car module, and do not switch cargo to per-row VAT — combined-base single VAT is the confirmed billing structure.

- **Re-Export** — Follows the Cargo combined-base model, generalized across N Bill of Entries instead of two portions: each BE contributes a `vatBase` (wharf rent + river dues + hoisting + re-shipment + removal, Levy excluded), `reexportCompute()` sums them into `vatBaseTotal = r2(Σ vatBase)`, VAT is charged **once** via `calcVATmpa(vatBaseTotal, vatRate × 100)`, and `levyTotal` (Σ per-BE Levy) is added after VAT via `grandTotal = r2(vatBaseTotal + vatAmount + levyTotal)`. Per-BE result sections on screen/print show only their `vatBase` sub-total; a single combined summary block (`buildCombinedSummaryPrintSection`, reused as-is from the Cargo print path) renders `vatBaseTotal → vatAmount → levyTotal → grandTotal`.

**Split billing** (23/07/2024 rate cut): When CLD ≤ 22/07/2024 and delivery ≥ 23/07/2024, `calcSlabs()` splits the period and applies old/new rates independently. Self-drive tons in Cargo also go through the same split logic via `calcCarBillingSdSlabs()`.

**Admin mode**: The admin button (`#adminBtn`) is **hidden by default** (`#adminBtn { display: none }`) and only shown with `.active` class after login (`#adminBtn.active { display: inline-flex }`). Access is via **Ctrl + Shift + Click** anywhere on the page, which calls `toggleAdmin()` and opens the login modal. Default credentials: `admin` / `admin`. Admin unlocks rate inputs (removes `.ro` class) and reveals `#resetRatesBtn` (which IS hidden by default via `style="display:none"`). Locked after 5 failed attempts (sessionStorage counter). On successful login `doLogin()` stores the entered password in `_sessionWriteToken` (module-scoped, memory only — never localStorage); `toggleAdmin()` clears it on logout. This token is sent as a `Bearer` header on all Cloudflare Worker PUT requests via `putHeaders()`.

**Confirm dialog**: `confirmModal(message)` is a Promise-returning helper that shows `#confirmDialog` (a native `<dialog>` using the same `showModal()` / `close()` pattern as `#overlay`). It resolves `true` on OK and `false` on Cancel. All destructive actions that previously used `window.confirm()` or `confirm()` must use `confirmModal()`. Both `resetRatesToDefaults()` and `deleteSavedBill()` are `async` functions that `await confirmModal(...)`.

**Module-aware accent system**: `style.css` defines `--accent`, `--accent-hi`, `--accent-lo`, `--accent-bg`, `--accent-bdr`, `--accent-ring`, `--accent-rgb` as CSS custom properties defaulting to gold (Car module values). `switchModule()` in `src/admin.js` calls `document.body.classList.toggle("mode-cargo", mod === "cargo")` and the equivalent `mode-reexport` toggle, which trigger the `body.mode-cargo` (sky blue) / `body.mode-reexport` (teal, `--teal: #10b981`) rules in CSS that override every `--accent-*` variable. All UI elements (tabs, inputs, grand total box, section rows, date displays, print button, search bar) consume `var(--accent)` — no module-specific duplicate rules needed. The printed invoice resolves accent to literal hex values at generation time since the `<iframe>` has no access to parent CSS vars: `buildInvoiceHtml(opts)` picks a palette from `opts.accent` (`"car"` | `"cargo"` | `"reexport"`), falling back to the legacy `opts.isCargo` boolean when `accent` is omitted so existing Car/Cargo call sites are unaffected.

**Lock icon (`.lck`)**: All lock icons use `<span class="lck"></span>` — never emoji. The `.lck` CSS class renders a padlock via `mask: url(svg)` and `background: currentColor`, so it inherits color from context (including accent-aware parents). Emoji alternatives are banned; they render inconsistently across platforms.

**Date field wrapper (`.date-field-wrap` / `.cal`)**: All date inputs are wrapped in `<div class="date-field-wrap">` with a sibling `<span class="cal"></span>`. The `.cal` class renders a calendar SVG icon via `mask: url(svg)` and `background: var(--accent)`, positioned absolutely inside the wrapper (`right: 10px`, `pointer-events: none`). Date entry is always manual `DD/MM/YYYY` — the icon is decorative only. There is no JS calendar picker.

**Date field hint**: Every date field has a `<div class="field-hint hint-muted" id="{fieldId}-hint">DD/MM/YYYY</div>` sibling after the `.date-field-wrap`. `validateDateField(inputId, hintId, label)` calls `setFieldState()` to switch the hint between `hint-muted` (empty), `hint-error` (invalid), and `hint-ok` (valid). Called from `carRefreshNow()` and `cargoRefreshNow()`. Applies to: `cld`, `delivery`, `car-billEntryDate` (Car module) and `c-cld`, `c-delivery`, `c-billEntryDate` (Cargo module). B/E Date is optional — empty is valid (shows muted placeholder), but if non-empty it must be a valid DD/MM/YYYY date.

**Grand total pulse**: After each bill calculation, `carCalculate()` and `cargoCalculate()` trigger a CSS pulse on the grand total box: `el.classList.remove("just-calculated"); void el.offsetWidth; el.classList.add("just-calculated")`. The reflow (`void offsetWidth`) restarts the animation even on consecutive calculations. The `gboxPulse` keyframe is suppressed by `prefers-reduced-motion`.

**Rate table inputs vs. spans**: Each editable rate has a hidden `<input>` and a visible `<span>`. `syncSpan(inputId, spanId)` keeps them in sync. In admin mode the span is hidden and the input is shown.

**Bill of Entries field polish** (Re-Export): `renderBillOfEntries()` (both the Overside flat branch and the Port Side branch with nested `.re-cld-list`) wraps every tonnage `<input>` (BE Ton, CLD Ton, Removal Ton) in `<div class="in-unit-wrap">…<span class="in-unit">ton</span></div>` — a reusable inline unit-suffix adornment (CSS: `.in-unit-wrap`/`.in-unit`, positioned like the existing `.date-field-wrap`/`.cal` pattern) that never overlaps typed digits (`padding-right` on the input reserves the space). Field `<label class="lbl">`s carry small inline SVG icons (`RE_ICO_HASH`, `RE_ICO_CAL`, `RE_ICO_TON` consts defined just above `renderBillOfEntries()`) — hash for BE Number, calendar for date fields, box for tonnage. `.re-cld-actions` (the "+ Add CLD" / Removal Ton row) has a dashed top divider separating it from the CLD lot rows, and Removal Ton's `.fg` is width-capped (~160px) so it doesn't stretch the row. None of this touches input `id`s, `oninput` handlers, or values — purely presentational, so `reexportCompute()`, `billInputSnapshot()`, and draft/save restore are unaffected.

**Part billing stages** (Cargo only): Stored in the DOM as dynamically rendered rows under `#c-pbStagesContainer`. Stage objects: `{ date, insideAfter, outsideAfter, sdInsideAfter, sdOutsideAfter }`. `computePartBillingWharfrent()` iterates stages, keeping slab day-count running continuously from CLD — day count never resets between stages, only weight changes. When Self Drive is active, each stage shows SD balance inputs clamped by `pbMaxSdWeight(idx, side)`. Changes to SD balance inputs are handled by `pbSdBalanceChange(idx, side, rawVal)`. Stages whose delivery falls **within free time** get `freeTimeDelivery: true` on the period object — they appear in bill tables and stage counts with a "Delivery within free time — no wharfrent charge" label rather than being silently skipped.

**Self Drive** (Cargo): A standalone `.sd-card` above the Payable Charges section — **independent of the Hoisting checkbox**. `wharfSdInside` / `wharfSdOutside` are computed regardless of whether hoisting is checked. SD tons are billed at Car Billing slab rates via `calcCarBillingSdSlabs()`.

**Global state flags** (Cargo): `cargoIncludeWharfrent` (bool, default `true`) and `cargoIncludePayables` (bool, default `true`) control whether those sections appear in the printed invoice. Both are toggled by checkbox controls in the cargo results header and both are reset to `true` in `cargoReset()`.

**Placeholder pattern**: All user-facing quantity inputs use `placeholder="0"` — never `value="0"`. Part billing balance inputs follow the same rule. In `pbBalanceChange()` and `pbSdBalanceChange()`, `rawVal` is passed as a string (`this.value`). Assign `inp.value = isEmpty ? '' : clamped` — empty string (field cleared) shows placeholder, explicit "0" typed by the user shows 0.

**Toggle-switch checkboxes** (`.pc-toggle`): The native `<input type="checkbox">` inside every toggle is visually hidden (`opacity:0; width:0; height:0`). Do not try to interact with it via Playwright `click()` or `check()` — it will report as not visible. Instead set state programmatically: `el.checked = true; el.dispatchEvent(new Event('change', { bubbles: true }))`. To click via CSS, click the `.pc-toggle` label element, not the input.

**Free time = 0**: Supported in both modules. When `freeDays === 0`, wharfrent starts on CLD itself: `freeDays === 0 ? addD(cld, -1) : addD(cld, freeDays - 1)`. The free-time strip shows "No free time" instead of day pills.

**Date validation (`isValidDateStr`)**: After constructing `new Date(y, m-1, d)`, the validator re-checks `getFullYear/getMonth/getDate` against the parsed parts. This **calendar rollover guard** means `31/02/2024` fails (JavaScript would silently roll it to March 2) rather than producing wrong billing periods. Do not remove or weaken these post-construction checks.

**Pre-calculate input validation**: `collectCarErrors()` / `collectCargoErrors()` return an array of `{ id, msg }` for every failing input; `reportInputErrors()` surfaces them in one toast (`white-space: pre-line`, so `\n`-joined messages line-break) and focuses the first offending field. `carCalculate()`, `cargoCalculate()`, and `printBill()` all gate on these — they abort before any compute/render when errors exist. Guards are validation-only and never alter a calculation. Current guards: CLD + delivery date format (including rollover), delivery-not-before-CLD, optional B/E Date format when non-empty, **vehicle weight > 0** (Car), **total weight > 0** (Cargo, blocks the all-zero bill that `0 inside + 0 outside == 0 total` would otherwise pass), inside+outside == total, and removal/weighment/self-drive tonnage bounds. The `carCompute()`/`cargoCompute()` `Number.parseFloat(...) || default` fallbacks are deliberately permissive for the live preview path (`carRefreshNow`/`cargoRefreshNow`, wrapped in try/catch) — the error gate is what protects the actual bill.

**Toast notifications**: `showToast(msg, type)` where `type` is `'success'|'info'|'warning'|'error'`. Creates `#pb-toast` lazily on first call.

**XSS guard**: `escHtml()` must be used for all user-supplied or remotely-loaded text injected into `innerHTML`. Current coverage: BL Number, C&F Agent Name, bill entry number, bill entry date, part-billing stage dates, rotation registry rows (`r.num`, `r.cld` in `renderRotationTable`). `r.id` is `Date.now().toString()` (numeric string, safe in onclick). `r.year` is the result of `parseInt` (number, safe). Any new field sourced from user input or GitHub storage must go through `escHtml()` before innerHTML interpolation.

**DOM caching**: `domCache` object holds references to frequently updated elements, populated by `initDomCache()` on DOMContentLoaded.

**Saved bills search**: `_sbCarSearch` / `_sbCargoSearch` (module-level strings) hold the current search query for each panel. `sbSearch(type, q)` updates the relevant variable and calls `renderSavedBills()`. `matchesBillSearch(b, q)` checks bill number, CLD, delivery, C&F name, BL number, and total formatted amount. `buildRows(bills, searchQ)` filters internally — the full `bills` array is passed (for the "no saved bills" empty state) and filtered to `visible` for the "no match" state. Column count is 8; the empty-state `colspan` must stay at `8`.

**Print from saved bills**: `printSavedBill(billNumber)` calls `editSavedBill(billNumber)` (which restores the form and switches module) then `setTimeout(() => printBill(type), 80)`. The 80 ms delay allows the module switch and DOM update to settle before `printBill` reads the rendered result. Do not collapse this to synchronous — `printBill` reads the live DOM.

**Draft auto-save**: `DRAFT_KEYS = { car: 'pb_draft_car', cargo: 'pb_draft_cargo' }`, TTL 24 hours. `saveDraft(type)` snapshots via `billInputSnapshot(type)` and stores `{ ts, inputs }`. `restoreFormDraft(type)` only restores when `hasMeaningfulDraft(inputs, type)` is true — checks for non-empty `blNumber`, `cnfName`, or non-default `billEntry` (`!== 'C-'`). Restore runs inside `setTimeout(0)` in `DOMContentLoaded` so it fires after the date-defaults initialisation. `clearDraft(type)` is called from `carReset()`, `cargoReset()` (the originals), and `saveBill()`. The `carReset` patch (bottom of file) also calls `clearDraft('car')`.

**Service worker versioning**: The cache name is `portbill-v17` in `sw.js`. Every production deploy that changes any cached asset must increment this string (e.g. `portbill-v18`). The `activate` handler deletes all caches whose names don't match the current version.

**Offline sync resilience (v3.12.0)**: Cloud writes (`saveRotationsToWorker`, `saveBillsToWorker`, `saveConfigToWorker` in `platform.js`) can fail while offline or mid-network-error. Rather than silently losing the change, each writer catches the failure and calls `markPending(resource)` (`resource` is `'rotations'` | `'bills'` | `'config'`, tracked in the `SYNC_PENDING_KEY` `localStorage` object defined in `core.js`); a successful write calls `clearPending(resource)`. `updateSyncBadge()` reflects this state in the header `#syncBadge` pill: hidden when online with nothing pending, `Offline` (amber, `.sync-offline`) when `navigator.onLine` is false, `Syncing N…` (accent-colored, `.sync-pending`) when N resources have unflushed local changes. `window.addEventListener('online', …)` fires `updateSyncBadge()` + `flushSync()`; `'offline'` fires `updateSyncBadge()` only. `flushSync()` is a **whole-state last-write-wins** re-push — no per-change op log, each resource is just re-`PUT` in full from its current local snapshot (`getSavedBills()` for bills, the `ROTATIONS_KEY` cache for rotations, `getAdminPasswordHash()` for config) once connectivity returns; rotations/config are only flushed when `isAdmin && _sessionWriteToken` (they're admin-gated writes). On page load (`DOMContentLoaded` in `platform.js`), `flushSync()` runs **before** `loadBillsFromWorker()`, and the cloud-bills pull is skipped entirely if `getPending().bills` is still true after that flush — this ordering exists specifically so a bill saved while offline can never be silently overwritten by a stale cloud copy on the next load. Rotations get a parallel resilience path independent of the pending-write system for **reads**: `loadRotations()` (`car.js`) writes every successful fetch to the `ROTATIONS_KEY` cache and reads that cache back on fetch failure, so a network error never blanks the rotation UI. On the **write** side, `addRotation()`/`deleteRotation()` (v3.12.1 fix) commit the mutation to `_rotations`/`ROTATIONS_KEY`/the UI unconditionally, *then* call `saveRotationsToWorker()` — before this fix the local commit was wrongly gated on the Worker PUT succeeding, so an offline add/delete reported "failed" and vanished instead of being queued; `flushSync()` would then re-push the stale pre-change `ROTATIONS_KEY` snapshot and silently clear the pending flag, permanently losing the edit.

**Usage analytics privacy**: Tracking is anonymous by design — a random UUID per browser, no IPs, no names, no PII, no cookies. Never add personal data to the `/track` payload. The Analytics module (`#page-stats`) is admin-gated exactly like rotation/saved: listed in the `switchModule()` guard and in `updateAdminNavigation()`.

## Rate IDs

Car module uses plain IDs (`nr1`, `nr2`, `nr3` for new rates; `or1`, `or2`, `or3` for old rates; `rRiver`, `rLanding`, etc.). Cargo module mirrors with `c-` prefix (`c-or1`, `c-rRiver`, etc.). Re-Export module mirrors with `re-` prefix (`re-rRiver`, `re-wharfLow`, `re-land1..3`, `re-hoistPct`, `re-reshipSame`/`re-reshipDiff`, `re-removalMult`, `re-rLevy`) plus `reexport-freeDays`/`reexport-vatRate` for the two fields that (like Car's `freeDays`/`vatRate`) have no paired display span. `RATE_DEFAULTS` is the authoritative source of factory defaults.

**Rate display-span convention**: `loadSavedRates()` derives each admin rate's paired display `<span>` id generically — `"c-d" + id.slice(2)` when `id` starts with `c-`, otherwise `"d" + id` — so any new rate's hidden `<input id="re-wharfLow">` must pair with `<span id="dre-wharfLow">` (not `re-dwharfLow` or similar) for this fallback to resolve it without touching `loadSavedRates()`. `applyAdmin()`, unlike `loadSavedRates()`, does **not** use this generic formula — it hardcodes explicit per-module ID arrays (one readonly-toggle group, one span-pair group) for Car, Cargo, and Re-Export each; a new admin-editable rate must be added to the matching Re-Export array in `applyAdmin()` or it will stay permanently locked regardless of admin state.
